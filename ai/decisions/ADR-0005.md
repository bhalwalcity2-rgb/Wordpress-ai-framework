# ADR-0005: Homepage Content Is Additive, Not a Replacement

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-09-03 |

## Decision

The homepage may carry a content file at `content/pages/home.json`, validated by `home.schema.json`. Unlike a location or service file it is **additive**: `front-page.php` keeps its frozen section order and renders these sections into it rather than replacing the layout. It has no `city` or `state`, and does not create a URL.

## Context

`content/locations/las-vegas.json` holds 363 written words for a page that architecturally cannot exist — Las Vegas is the primary city, so the homepage owns that intent (ADR-0004). The prose had nowhere to go.

The homepage also already carries long-form written prose, in `business-config.php` under `homepage_intro.paragraphs`. That is the wrong home for it. `business-config.php` is the file you replace when the theme is reused for another business; three paragraphs of Las Vegas copy are not reusable business configuration. And config cannot express what the content contract already can — sub-blocks, reference tables, images, per-section eyebrows.

The obvious move, giving the homepage the same treatment as a location page, is wrong. A location page's content file *replaces* the generic layout, because the generic layout is the templated output being eliminated. The homepage has no sibling to be templated against — there is exactly one — and its section order is frozen by the Master Website Creation Workflow. Replacing it would discard the intro, services grid, differentiators, and service-area grid for no benefit.

## Alternatives Considered

- **Reuse `location.schema.json` for the homepage** — Rejected. It requires `city`, `state`, and `slug`, all of which invite the homepage to be treated as a location page. A file with a `slug` is one refactor away from acquiring a URL, which is the cannibalisation this architecture exists to prevent.
- **Replacement semantics, as location and service pages use** — Rejected. Discards the frozen homepage composition to solve a problem the homepage does not have.
- **Move `homepage_intro` prose into the content file now** — Deferred, not rejected. It is a lossless migration the architecture now supports, but it is a content change, and this ADR is a contract change. Doing both at once makes it impossible to attribute any difference in output.
- **Leave the homepage config-only and delete `las-vegas.json`** — Rejected. Destroys 363 words of written prose to avoid adding one optional loader.

## Consequences

- `content/pages/home.json` is optional. No file is shipped with this decision, so the homepage renders today exactly as it did before — the branch is inert until content exists.
- The section dispatch was extracted from `written-page.php` into `template-parts/sections-loop.php`, so the homepage and written pages render canonical sections through one code path. A section type added to one is available to both.
- `seo_title` / `seo_description` in the file override `seo.home_title` / `seo.home_description`; both remain optional and fall back to config.
- The schema forbids `city`, `state`, and `slug` outright, so the homepage cannot drift into being a location page.
- Migration path for `las-vegas.json`: move its sections into `content/pages/home.json` verbatim, confirm the rendered word count matches, then delete the location file. Ordinary content work, no further contract change.
- `homepage_intro` stays in config for now. Moving it is the same migration and can happen at the same time.

Contract: `content-engine/config/schema/home.schema.json`. Rendering: `front-page.php`, `template-parts/sections-loop.php`.
