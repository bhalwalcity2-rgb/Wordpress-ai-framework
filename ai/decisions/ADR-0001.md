# ADR-0001: Kadence as the Default Page-Building System

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-08-01 |

## Decision

Every page starts with Kadence Theme + Kadence Blocks Pro. Elementor is used only when a documented layout requirement exceeds what Kadence can deliver, and the justification is recorded per-page (see `ELEMENTOR_STANDARDS.md` §2).

## Context

The framework needed one default page-building system to keep output consistent across projects and AI sessions. Two capable tools exist in the approved stack — Kadence Blocks and Elementor — and without a stated default, every page risked becoming a case-by-case tool choice, undermining consistency across projects.

## Alternatives Considered

- **Elementor as default** — Rejected. Elementor's baseline cost is 200–500 KB of CSS/JS before any content is added, and it produces significantly more DOM nodes than Kadence for equivalent layouts (`ELEMENTOR_STANDARDS.md` §1).
- **No default, choose per page** — Rejected. Produces inconsistent output across projects and AI sessions, and undermines the QA checklists in `KADENCE_STANDARDS.md` §15, which assume Kadence-by-default.
- **Kadence-only, no Elementor** — Rejected. Some layouts (dynamic ACF-driven location pages, complex overlapping hero sections, mega menus) are impractical in Kadence Blocks alone; forcing them into Kadence would produce worse output than a justified, contained Elementor exception.

## Consequences

- Every new page defaults to Kadence Blocks unless a documented exception exists.
- Any page built in Elementor requires its own justification note (`ELEMENTOR_STANDARDS.md` §2).
- Headers and footers are never built in Elementor, regardless of page-level exceptions — Kadence's header/footer builder is the standard in all cases.

Full implementation rules: `KADENCE_STANDARDS.md`, `ELEMENTOR_STANDARDS.md`.
